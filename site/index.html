How this works

        
Agents that run without close supervision often leave traces in public records: URL scanners that publish every scan, web archive indexes, and certificate logs. This toolkit follows the methods in public incident reports from
          swarmcha.se and
          Transluce.

        
    
          
  1. Unwrap each URL through relays, carriers, data: programs and base64 parameters to find the real target.
    2. 
          
  2. Match indicator rules: relays, attack payloads, agent tags, callback inboxes, header fingerprints, and residue of model output (Markdown around URLs, unfilled placeholders, tool-call markup).
    3. 
          
  3. Grade each record: significant, suggestive or noise. A single relay hit is never enough.
    4. 
          
  4. Link records into clusters by shared inbox IDs and tags, by timing against the same target, and by probe chains (variants of one request minutes apart).
    5. 
          
  5. Time the clusters: cadence, bursts, pauses, daily rhythm, and the operator's likely UTC offset from date tags. Reports add hints: URL encoding style, stale date tags, recon openings and unusual path sets shared across hosts, invented identifiers, and pauses two clusters share. Hints change no score and merge nothing.
    6. 
          
  6. Report: draft notices for the AI provider and for affected operators, with defanged evidence.
    7. 
          
  7. Watch: a scheduled job pulls new records, emails a digest, and checks open cases for new activity.
    8. 
        

        
Methodology covers each step in detail.

        
Ground rules

        
    
          
  • Collect passively. Never open the URLs agents submitted, and never read or post to their callback inboxes or topics.
    • 
          
  • Model names in requests are weak evidence. Agents misreport who built them.
    • 
          
  • An ASN names the host, not necessarily the developer.
    • 
          
  • Swarms are active incidents: reports to the provider and affected operators, and the public notice, go out together.
    • 
          
  • Cookies, tokens and API keys in records are replaced with hashes before analysis.
